# 审核自动化分工提示

用途：告诉你（审核 agent）每条清单项**该靠什么完成**，避免两类浪费——脚本已覆盖的条目逐字重查（浪费时间），或必须读原文的条目只看脚本线索（漏判）。

**先做一件事**：打开 `.workpaper.md` 和 `evidence.json` 后，先摘出证据包——封面、样品信息、引用标准、汇总表、结论、正文声明的关键图/表/照片，以及全部 `⚠️` 图片/图表对象标记。后续所有问题都从这批证据起步；语言审核使用 `language-review-input.json`，图表审核使用 `figure-review.json`。

| CHECK-2 日期逻辑 | DC-B02、DC-D03（校准过期）、CD-S08、CD-S03（日期层面） |

注意：脚本输出是**线索**，采纳前必须回第二部分原文核对上下文，防止误报写入报告。

## 二、半自动（脚本给线索，必须人工/语义确认）

- **DC-D03 校准有效性**：脚本只比对文本声明的日期，证书真伪、认可范围 → 人工核对项
- **DC-C05 / DL-C04 编号**：脚本能发现写法不一致和疑似笔误，但哪个是正确编号 → 人工确认
- **DL-B01 单位**：脚本只查部分常见写法，其它单位靠你读原文时留意
- **DC-F02 / DC-F03 / DC-F06 / DC-F07 / DC-P03 / DC-P04 / DC-P06**：脚本能标出图片页、图表对象或正文引用，但图像内容、图文是否一致，必须靠视觉或人工判断

## 三、视觉优先（有视觉能力时先看图；没有时转人工核对）

- 关键结论依赖**截图、照片、曲线趋势、状态灯、界面弹窗**时，优先做视觉复核；没有视觉能力时不得写成确定性缺陷。
- 先做“**应有 vs 实有**”图/表/照片清单：正文说“见下图”“附照片”“如图 3 所示”却找不到对象，通常是 DC-F06 / DC-F07 / CD-G11。
- 视觉结论也要落回文本证据：至少记录位置索引、观察对象、你为何判断一致/不一致；拿不准就归入人工核对项。

## 四、纯语义（必须读原文判断，脚本帮不上）

- **DL-A02~A06**：判定方向、临界值（**DL-A03 需自行计算 |实测−限值|/|限值| 是否 <5%**）、最严值判定、数据与结论矛盾的单项层面、试验条件对照
- **DL-C02 / C03 / C05 / C06**：文字 vs 表格 vs 曲线/截图趋势矛盾、试验条件前后一致、同参数多处数值一致、图/表/正文相互引用是否支持同一结论
- **DL-D01~D04**：结论是否超出数据支持、外推依据、失效闭环、样本量
- **DC-A / B 签署资质**、**DC-E01 / E03 / E04 追溯**、**DC-F 五要素与图表要素**、**DC-G 结论表述**、**DC-J01~J03 中英技术语言**、**DC-P01~P06 PPT 呈现**

## 五、易漏提醒（历史审核中 AI 最常漏的）

1. **DL-A03 临界值**：看到“实测值接近限值且判合格”就要算裕度，不要滑过去
2. **判定方向用反**：`不大于/≥/≤` 与数值比对逐条过，尤其限值单位与实测单位不一致时
3. **结论章 vs 单项章**：结论写“无异常/全部通过”时，回单项逐条对一遍
4. **百分比基准**：容量保持率、SOC 未说明相对基准（DL-B04）
5. **双语术语**：中文术语、英文缩写、页标题三处可能各写一套，别把它当成纯格式问题
6. **图表清单**：正文承诺了图/表/照片，但实际没有、编号断裂或无法支撑结论，是高频漏判点
7. **置信度纪律**：没有 `位置 + 摘录 + 预期/实际`，不要成案；没有视觉能力，不要写低置信度图像定论
